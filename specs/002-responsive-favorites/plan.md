# Implementation Plan: Responsive Layout and Favorites Controls

**Input**: `specs/002-responsive-favorites/spec.md`

## Summary

Improve existing Random Gallery layouts from 320–1440 CSS pixels, including short dialogs,
long filenames, both themes, and desktop zoom. Replace font-dependent hearts in Gallery and
ImageViewer with one native button containing a local SVG. Preserve the collection owner,
confirmed-save behavior, IndexedDB schema, navigation, and themes.

Assumptions follow spec A-001–006: this is an incremental enhancement of the implemented app.
Reuse the installed stack and test harness without adding packages. Breakpoints are design
choices; 24-pixel hearts, 44-pixel targets, contrast and state preservation are fixed requirements.

## Technical Context

**Language/Version**: Strict TypeScript (`^5.9.3`, ES2022 target), TSX; Node >=24.

**Primary Dependencies**: Existing React/React DOM `^19.3.0`, Vite `^8.1.3`, React plugin
`^6.0.3`, Tailwind/Vite integration `^4.3.2`. These are package.json declarations, not claims
about upstream releases. Extend existing CSS; no new icon, state, routing, or dialog library.

**Storage**: Preserve IndexedDB `random-gallery` version 1, `images` and `blobs` stores, and
localStorage `random-gallery.theme`. Pending/error state remains transient.

**Testing**: Existing Node built-in unit runner and Playwright `^1.63.0` browser/storage
integration harness. Reuse genuine fixtures, transaction locks, and abort injection. Baseline
planned component-emulator tooling remains unavailable; this feature does not close that gap.

**Target Platform**: Baseline current/previous stable desktop Chrome, Edge, Firefox, Safari at
release; mobile Chrome/Android and Safari/iOS. Automated Chromium/Firefox/WebKit plus actual
browser/device checks with recorded versions. HTTPS or localhost.

**Project Type**: Existing static client web application; Random and Gallery, no server API.

**Performance Goals**: Preserve baseline p95 shuffle/search <=1 second for 100 images up to
2 MiB; processing feedback <=1 second. No new blob loads, storage scans or viewport-driven
component remounts. No new performance target.

**Constraints**: Device-only data; no remote icons/fonts, services, migrations or new features.
Whole images remain uncropped. State survives reflow/orientation/zoom. Favorite indication
changes only after commit. Both themes satisfy spec contrast thresholds, including pending
controls. Favorite targets >=44 × 44 CSS pixels; heart SVG 24 × 24 CSS pixels.

**Scale/Scope**: Gallery thumbnail, inline Random and modal preview favorites; existing upload,
navigation, empty/error/loading states; preview and deletion dialogs. No collection-size cap.

## Phase 0: Research Outcome

[research.md](research.md) resolves design choices using implemented code and baseline evidence.
Start with existing breakpoints, fix intrinsic sizing/wrapping, bound both dialogs vertically,
and use matching outline/filled SVG geometry. Reuse pessimistic mutations and per-image locks.
Preserve preview selection independent of filtered results and existing focus fallback.

## Phase 1: Behavior and Interface Design

- **US1 / FR-001–005**: Fix flex/grid shrinkage, header wrapping, long labels/messages, action
  spacing and bounded dialog scrolling in styles.css. Keep DOM/state mounted through reflow.
  Gallery may reduce columns to preserve usable captions/targets. Existing `overflow-x: clip`
  cannot prove fit: measure descendant bounds and inspect with clipping disabled. Preserve
  `object-fit: contain` for whole-image views.
- **US2 / FR-006/008/010/011**: Introduce FavoriteButton and use it in Gallery and both
  ImageViewer modes. One decorative SVG path, 24 × 24 pixels, outline when false and filled when
  true. Fixed button geometry, saved aria-pressed/icon state during pending, native disabled and
  aria-busy. Override inherited disabled opacity for this control to preserve required contrast.
  Existing useCollection prevents same-ID conflicts and publishes changes after commit only.
- **Error/retry**: Keep actionable messages and retry in the current view. Modal preview needs
  its own message because background alerts are outside its active dialog. Reuse current error
  ownership unless a failing scenario proves it insufficient. Reactivation retries after failure;
  any retry callback must resolve the current saved record rather than invert stale metadata.
- **US3 / FR-007/009/012/013**: One native button, image-specific action name, saved pressed
  state, aria-hidden/nonfocusable SVG, >=44-pixel target and visible focus. Keep targets separate
  from thumbnail opening and deletion. Preserve modal initial focus, containment, Escape, nested
  confirmation, and return to origin or surviving thumbnail/Gallery heading. The heading already
  has tabIndex -1; strengthen regression checks before changing working focus behavior.
- **Preservation / FR-014**: Preview lookup stays against the complete collection. Random retains
  existing eligible-ID reconciliation/non-repeat behavior. No storage migration, endpoint,
  blob conversion, theme rewrite or unrelated baseline cleanup.

Details: [data model](data-model.md), [UI contract](contracts/user-interface.md), and
[favorite state contract](contracts/favorite-state.md).

## Implementation Sequence and Verification

1. Capture baseline checks and reproduce relevant failures before changes; verify typecheck,
   unit/build and targeted browser checks, recording infrastructure limits separately.
2. Deliver US1 through narrow layout edits; verify viewport/theme/state matrix, actual action
   bounds, short-dialog scrolling, resize preservation and real desktop 200% zoom.
3. Deliver US2 shared button/state/error integration; verify geometry and real pending,
   commit, abort, retry and repeated-activation scenarios in all three contexts.
4. Deliver US3 input/accessibility refinements; verify Enter/Space, names/pressed state,
   non-overlapping targets, focus fallback, and contrast in both themes including pending.
5. Verify data retention, Random scope/non-repeat, search/filter, confirmation/delete and privacy;
   record evidence without treating authored/discovered tests as passed tests.

US1 is the smallest independently useful increment. US2 can proceed independently after the
baseline audit. US3 builds on the shared control. Baseline unfinished tasks retain their scope.

## Verification Strategy

Follow [quickstart.md](quickstart.md). Use browser assertions for measured CSS, native dialogs,
SVG/accessibility and native storage interactions. Preserve existing regression assertions and
reproduce bugs before fixes as required by the constitution. The specification explicitly calls
for scenario validation; avoid tests that merely mirror component implementation.

Baseline [validation.md](../001-random-gallery/validation.md) records server/browser permission
failures, missing tooling and manual evidence. These are historical observations, not newly
executed results or resolved gates. Record commands, versions, counts, traces/screenshots and
manual results during implementation. Viewport emulation does not establish physical touch
behavior or actual browser zoom. No implementation or runtime acceptance is claimed by this plan.
